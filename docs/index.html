Rust crates arrayref, internment, append-only-vec compromised with build-time credential stealer

A compromised maintainer account pushed malicious releases of three widely-used Rust crates — arrayref (245M+ total downloads, 403 dependents), internment, and append-only-vec — alongside a typosquat of proc-macro2. The build script downloads and runs a remote payload during compilation with no function call required, disables TLS validation, steals Chrome/Brave/Edge browser credentials, and installs OS-appropriate persistence (Registry, LaunchAgent, systemd). Nextron Systems caught it 07:15 UTC Aug 20; all three crates were pulled within 86-107 minutes, and researchers noted infrastructure overlap with prior North Korea-linked npm supply-chain operations. Durable catch: HTTPS POST beacons to /49890878 or any host resolving hwsrv-798836[.]hostwindsdns[.]com — that traffic means the build-time implant ran, regardless of which crate pulled it in.

CVE-2026-33824 — Windows IKE Extension double-free RCE, actively exploited

A double-free (CWE-415) in the Windows IKE and AuthIP Keying Modules service lets an unauthenticated remote attacker achieve code execution by sending malformed IKEv2 fragments to UDP port 500 or 4500 on any Windows 10, Windows 11, or Windows Server host with IKE enabled — no user interaction required. Microsoft shipped the fix in April 2026; CISA confirmed active exploitation and added it to KEV Aug 18 with a 3-day federal remediation deadline. Durable catch: inbound UDP/500 or UDP/4500 traffic from outside your expected IPsec peer set — Ray-style scanning of these ports for unpatched IKE Extension hosts is the precursor to exploitation.

REPORTED 2026-08-19ACTIVE SINCE 2026-08-18 CWE-415 DOUBLE-FREE · UNAUTH RCE UDP 500/4500 · WORMABLE ACROSS ALL SUPPORTED WINDOWS T1210 · T1190 BleepingComputer (Aug 19)
CVE · EXPLOITED · WORMABLE
ACTION Apply Microsoft's April 2026 security update immediately if not already deployed; block inbound UDP/500 and UDP/4500 at the perimeter for hosts that don't use IKE; restrict remaining IKE traffic to known peer IP addresses via firewall rule.

CVE-2025-62593 — Ray framework DNS-rebinding RCE, now KEV-listed and tied to crypto-mining botnets

Ray's job-submission endpoints (/api/jobs, /api/job_agent/jobs/) ship with no authentication by default. Attackers use DNS rebinding — a crafted website or ad that rebinds a domain to a victim's local or network-adjacent IP after passing a same-origin check — to make a developer's own browser submit malicious jobs to any reachable Ray instance. CISA added it to KEV Aug 17; the RondoDox DDoS botnet had already incorporated it two days before public disclosure, and the ongoing ShadowRay 2.0 campaign uses it to plant crypto-mining botnets on GPU clusters. Durable catch: any unauthenticated POST to a Ray cluster's /api/jobs or /api/job_agent/jobs/ endpoint from an unexpected origin — Ray was never meant to be reachable without a job submission client.

REPORTED 2026-08-18ACTIVE SINCE 2026-08-17 CVSS 9.4 · KEV ADDED AUG 17 SHADOWRAY 2.0 -> GPU CRYPTO-MINING BOTNETS T1190 · T1496 The Hacker News (Aug 18)
CVE · EXPLOITED · KEV
ACTION Upgrade Ray to 2.52.0 or later; never expose Ray dashboard/job endpoints directly to developer workstations or the internet — bind to localhost or place behind an authenticated proxy; audit GPU clusters for unexpected mining processes as a compromise indicator even after patching.

CVE-2026-32475 — Elementor Pro File Upload flaw lets unauthenticated attackers plant PHP web shells

Elementor Pro's Forms module validates a file's extension and moves it to disk in two separate loops that handle empty file entries differently — submitting two file parts for the same upload field lets an unauthenticated attacker slip past the extension blocklist entirely and write a live PHP file straight into the public uploads directory. Any site with a published page containing a Form widget with a File Upload field is exposed, which Patchstack calls "an extremely common, everyday configuration." Elementor shipped 4.2.2 on Aug 19, one day before Wordfence/Patchstack detail went public. Durable catch: any .php file appearing under wp-content/uploads/elementor/forms/ — that path should never contain executable code.

CVE · WORDPRESS · UNAUTH RCE

Operation CameraSwarm — 14,500+ Dahua IP cameras compromised via credential attacks and P2P relay abuse

A Russian-speaking, unattributed operator compromised 14,530+ Dahua IP camera IPs between Jun 17-Jul 22 using three converging techniques: direct credential attacks against 12,324 IPs, two-year-old authentication-bypass flaws (CVE-2021-33044, CVE-2021-33045) to configure 1,923 cameras with persistent accounts, and abuse of Dahua's Easy4IP P2P relay infrastructure to reach 283 NAT-protected devices with no prior authentication at all. Both 2021 auth-bypass CVEs remain in CISA's KEV catalog. Durable catch: any Dahua device account creation or config change coming through the Easy4IP P2P relay path rather than direct admin access — that channel bypasses authentication entirely.

CVE-2026-19478 — Critical GitLab GraphQL flaw lets unauthenticated attackers delete projects, exploited within minutes

A code-injection flaw in a GitLab GraphQL directive lets an unauthenticated remote attacker modify or delete public projects and user data with no victim interaction — the third major GraphQL-layer vulnerability GitLab has patched in 2026. GitLab shipped an out-of-cycle emergency patch Aug 17; WatchTowr reproduced the exploit within minutes of disclosure, and its honeypot network caught the first in-the-wild attempts shortly after. Evooo1Bot — Mirai-derived botnet with encrypted C2 and SOCKS5 proxy relay hits routers and IoT devices

A previously undocumented Linux botnet built on Mirai's DDoS engine, active since July 2026 and disclosed by FortiGuard Labs Aug 18. It chains 18 known CVEs across Alcatel OmniPCX, NETGEAR, D-Link, and Tenda devices for initial access, brute-forces SSH, intercepts HTTP Basic Auth credentials and cookies, and offers operators a SOCKS5 proxy relay on port 1080 alongside DNS/TCP/UDP DDoS capability — all coordinated over encrypted C2 on port 443 to blend with normal HTTPS traffic. Durable catch: unexpected SOCKS5 relay traffic on port 1080 from an IoT/router device, or that device making outbound port-443 connections it has no legitimate reason to make.

CVE-2026-73570 — Zimbra Collaboration SNMP command injection, actively exploited

An OS command-injection flaw in Zimbra's SNMP monitoring path lets an unauthenticated remote attacker run arbitrary commands as the zimbra user, on any deployment with SNMP trap notifications (snmp_notify) and the swatchdog watchdog service enabled — swatchdog runs by default wherever zimbra-snmp is installed. Zimbra fixed it in 10.1.20 on Jul 20; CERT Polska's Alert 145/2026 (Aug 17) confirmed active in-the-wild exploitation against unpatched instances. Durable catch: the Zimbra service restarting without an admin-initiated cause, paired with new files under /opt/zimbra/jetty/webapps/, /opt/zimbra/jetty_base/webapps/, or /tmp/ owned by the zimbra user.

InterLock published its claimed haul from the July 31 attack on Southeastern Oklahoma State University on Aug 19 — 710GB covering more than 90,000 students' records (SSNs, grades, financial aid, disciplinary and medical information under FERPA/HIPAA protection) plus employee personal and injury data. Threat actor "Satanic" leaks live Stripe merchant API keys and customer data for hundreds of accounts

A threat actor using the handle "Satanic" uploaded roughly 35GB of Stripe merchant data to the cybercrime forum PwnForums on Aug 18 — 1,033 live API keys across 669 merchant account folders, exposing 1,350,336 unique customer emails and 688,000 customer records with names, phone numbers, and IP addresses. Stripe's own platform was not breached; the keys belong to individual merchants, likely harvested from exposed code, misconfigured environments, or prior infostealer logs. Satanic told Hudson Rock researchers this dump is a fraction of a claimed 20,000-key haul and threatened further releases. Durable catch: any Stripe API key that appears in a public repo, CI log, or infostealer dump should be treated as burned the moment it's found — rotation, not monitoring, is the only real fix.
