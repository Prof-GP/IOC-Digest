"PHP2Shell" — two critical PHP core flaws drew millions of exploit attempts within hours of disclosure

PHP maintainers disclosed CVE-2026-109618 and CVE-2026-109619 (each rated 9.2) on Oct 21, two flaws in PHP's core request-handling that let an unauthenticated attacker execute code on any server running an affected build — no WordPress plugin, theme, or app-layer bug required, since the flaw sits in the PHP engine itself. Cloudflare reported exploit attempts climbing from thousands in the ten hours before disclosure to tens of thousands within 45 minutes of the public advisory, hundreds of thousands within two hours, and millions within the day; Amazon's threat intel team recorded a probe against a decoy server as early as Oct 17, four days before public disclosure. Fixes shipped same-day in PHP 8.5.12, 8.4.27, 8.3.36, and 8.2.35. WordPress said no core update was needed since the bug is in PHP itself, not WordPress code, pushing the patching burden onto hosts and server admins instead of site owners. Durable catch: Cloudflare observed attackers actively mutating payloads to slip past its emergency WAF rules within hours of them going live — a signed vendor patch is the only fix that holds; any WAF rule bought time, not closure.

Detection here is necessarily behavioral (anomalous PHP worker crashes/restarts, unexpected memory-handling errors in logs) rather than indicator-based.

"Plex2Shell" exploit chain hit vulnerable Plex Media Servers within a day of PoC release, dropped cryptominers

Researcher Zach Main reported four Plex Media Server flaws (CVE-2026-96652, -96654, -96655, -96656) to Plex on Jul 27; chained together they let an unauthenticated remote attacker execute code with the privileges of the Plex Media Server process. Plex shipped a fix in build 1.43.3.10861 in early August, but exploitation began roughly a day after Main published technical details and PoC code, with activity first observed against Plex honeypots on Oct 17 dropping cryptominers and proxy/relay software. CISA added all four CVEs to its Known Exploited Vulnerabilities catalog around Oct 21 and set an Oct 23 remediation deadline for federal agencies. Durable catch: the four-month gap between Plex's patch (early August) and the exploitation wave (mid-October) is the actual lesson here — the PoC publication, not the patch release, was what triggered mass scanning, so unpatched self-hosted media servers stayed exposed on a known-fixed bug for months before anyone came looking.

Public exploit released for critical FortiSIEM RCE a week after Fortinet's patch; in-the-wild exploitation claim disputed

Fortinet patched CVE-2026-106173 on Oct 13; Horizon3.ai published a working proof-of-concept exploit on GitHub a week later, Oct 20. Singapore's CSA issued an alert Oct 22 confirming the public PoC's existence, and Canada's Centre for Cyber Security updated its advisory on Oct 23 to state the flaw "is being exploited in the wild" citing open-source reporting — but a separate contemporaneous report found no independent source confirming actual exploitation, and the flaw is not in CISA's KEV catalog as of this writing. Sources also disagree on affected version ranges and CVSS scoring. We're including this one with that caveat explicit rather than presenting a contested claim as settled fact: a public, working PoC against an unpatched FortiSIEM instance is dangerous regardless of whether the "in the wild" claim holds up, since the one-week patch-to-PoC gap left plenty of time for mass scanning to begin quietly before any public confirmation. Durable catch: when multiple government advisories disagree on whether a flaw is actively exploited, treat the public PoC's existence — not the disputed attribution — as the operative risk signal and patch on that basis alone.

ClickFix operators exploited a Siemens Software Center DLL side-loading flaw to deploy malware via fake verification prompts

Siemens confirmed on Oct 19 that CVE-2026-110936 (CVSS v4.0 8.4), an uncontrolled-search-path flaw (CWE-427) in Software Center versions before 4.0.9.8, is being actively exploited in real attacks. Attackers pair a legitimate, digitally signed older Software Center binary with an attacker-supplied malicious DLL dropped in the same directory; because the legitimate executable itself is never modified, file-reputation and signature checks miss it entirely, and the malicious code runs with the trust of a signed Siemens binary. Siemens ties the activity to the ClickFix social-engineering technique — fake CAPTCHA/verification pages that walk a victim through copy-pasting a malicious command — delivered via a platform researchers track as Romulus. Durable catch: a signed, legitimate binary is not proof of a clean execution chain — defenders need to inspect adjacent DLLs, parent processes, and outbound connections around trusted executables, not just the executable's own signature, since that is exactly the gap this campaign is built to exploit.

Note archive.dll alone isn't proof of compromise — it's also a legitimate component in some unrelated Siemens/Vero Software products — so confirm by checking the calling executable and install path, not the filename alone.

CISA discloses three new access-control flaws in Hitachi Energy's MicroSCADA X SYS600 grid-control platform

CISA published ICSA-26-293-04 on Oct 20 alongside five other ICS advisories (HMS Networks PCAN drivers, WAGO OS Linux, Moxa AIG-302, and two Hitachi Energy RTU500 entries), disclosing CVE-2026-9852 (CSV injection, CWE-1236, CVSS v4.0 4.6), CVE-2026-9853 (unauthorized access to application objects, CWE-303, CVSS v4.0 8.5), and CVE-2026-9854 (RBAC privilege elevation, CWE-303, CVSS v4.0 8.5) in MicroSCADA X SYS600, a SCADA platform used by electric utilities for grid monitoring and control. Hitachi's own advisory (8DBD000249) and CISA both mark exploitation status as none observed — we're flagging that explicitly rather than implying active attack, since the honest state here is "disclosed, unpatched-for-one-version, not yet seen exploited." A fix to 10.8 closes CVE-2026-9852; CVE-2026-9853 and -9854 affect 10.8 as well, with Hitachi offering mitigation guidance rather than a vendor patch for the RBAC flaw. Durable catch: two of the three CVEs affect the current shipping version (10.8), not just the legacy branch — "update to the latest version" isn't a complete answer here, and utilities running MicroSCADA X need the specific Hitachi mitigation guidance for CVE-2026-9854, not just a version bump.
