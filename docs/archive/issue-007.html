CVE-2026-9586 — unauthenticated SQLi in Sangoma Switchvox VoIP platform exploited to drop reverse shells

Sangoma Switchvox's /pa endpoint, which parses XML requests from supported IP phones, passes user-supplied input straight into PostgreSQL queries without sanitization — CVE-2026-9586, CVSS 9.3. Horizon3.ai researcher Zach Hanley observed valid exploitation attempts against internet-exposed Switchvox devices starting Aug 30, with attackers using the SQLi to modify user records, escalate privilege inside the application, run OS commands on the underlying server, and drop reverse shells for remote access; CISA added it to KEV Sep 2 alongside evidence the same actors chained it with a JFrog Artifactory flaw to mint admin tokens for follow-on credential harvesting. Durable catch: a Switchvox box showing outbound connections to 176[.]65[.]148[.]184 on port 39323, or suspicious entries in /var/log/switchvox/db-quirks.log, has already been hit — those are Horizon3's specific observed indicators, not a hypothetical.

CVE-2026-49869 — Kestra OSS auth-bypass RCE exploited within days of disclosure to deploy crypto miners

Kestra OSS's AuthenticationFilter skips authentication for any request path ending in /configs, a suffix-match bug that lets an unauthenticated attacker create and execute arbitrary workflows as root — CVE-2026-49869, CVSS 10.0. WatchTowr observed in-the-wild exploitation starting Sep 1, four days after disclosure, with attackers minting admin tokens and enumerating users, groups, and credential sets; Microsoft separately reported the same flaw was likely exploited as far back as late June to establish reverse shells, run Docker container discovery, and deploy XMRig cryptocurrency miners. CISA added it to KEV Sep 2. Durable catch: any Kestra instance reachable at a URL path ending in /configs bypasses auth entirely — the bug is the routing suffix itself, not a credential or session flaw, so network-layer path restriction is the only mitigation short of patching.

Invisible Unicode tag characters split keywords to evade filters across a 3-month, multi-million-email phishing wave

Microsoft and Fortra's FIRE team detailed a phishing campaign that inserted invisible Unicode Tags-block characters (U+E0000-U+E007F) inside financial lure words — turning 'funding' into 'fun[invisible-char]ding' — so filters and regex-based keyword matching miss the term while the word renders normally to the recipient. Microsoft's detection signature recorded a spike from roughly 21,000 hits on Feb 8 to over 1.3 million the next day, peaking above 2.3 million messages on Feb 26 and staying elevated for about three months on a weekday-only cadence; the campaign used hundreds of disposable finance-themed sender domains and relayed messages through legitimate ActiveCampaign marketing-platform infrastructure to inherit its sending reputation. Durable catch: any inbound message containing Unicode Tags-block codepoints (U+E0000-U+E007F) anywhere in the visible text is definitionally this evasion technique — no legitimate email uses that block, so its mere presence is a higher-confidence filter signal than any keyword match it's being used to evade.

PHISHING · EVASION · EMAIL SECURITY

CVE-2026-82329 — JFrog Artifactory authentication bypass added to KEV, chained for admin token minting

CISA added CVE-2026-82329, a CVSS 9.8 improper-authentication flaw in JFrog Artifactory, to its Known Exploited Vulnerabilities catalog Sep 2 as part of a seven-CVE batch. CISA's advisory states unknown threat actors have weaponized this flaw alongside the Sangoma Switchvox SQLi (CVE-2026-9586) to deploy reverse shells and mint admin tokens for follow-on enumeration of users, groups, credential sets, and federated access topologies — meaning a compromised Artifactory instance becomes a pivot point into whatever CI/CD credentials and federated identities it holds. Neither CISA nor the researchers who reported it have published specific IOCs (IPs, hashes) tied to Artifactory exploitation specifically. Durable catch: Artifactory sits at the center of a CI/CD trust chain by design — an attacker who mints an admin token here doesn't need to compromise anything downstream, since Artifactory's own federated-access model does the enumeration for them.

Unit 42 documents ransomware attacker using AI agents to run an entire enterprise intrusion in under 10 hours

Palo Alto Networks' Unit 42 disclosed a ransomware intrusion in which a human attacker directed frontier AI models and agentic attack frameworks to carry out nearly every step of the attack chain — initial access through a public API endpoint, credential harvesting, privilege escalation to root, hijacking CI/CD pipelines to steal cloud access keys, and pivoting through the victim's own cloud AI services as post-compromise infrastructure — compressing an intrusion Unit 42 says would normally take human operators about two weeks into under 10 hours across more than 50 distinct ATT&CK techniques. The attacker had a documentation agent produce an 80-page technical security audit of the victim's environment as a parting artifact. Unit 42 has not named the victim organization, the AI framework or model used, or published technical indicators (IPs, hashes, tool names) tied to this specific intrusion. Durable catch: the compression from two weeks to under 10 hours, not any single novel technique, is the actual finding here — detection and response timelines built around human-speed attacker dwell time no longer hold against an agentic operator.

Settra, a double-extortion ransomware and data-theft group first identified in June 2026, listed Italian biotech firm DiaSorin S.p.A. on its Tor leak site Sep 3, claiming data theft from an estimated Aug 25 intrusion and threatening publication absent negotiation over Tox messaging. Across its confirmed victims, Settra has used a known-vulnerable Safetica process-monitoring driver, STProcessMonitor_v114.sys (CVE-2025-70795), in a bring-your-own-vulnerable-driver technique to kill EDR/AV processes from kernel context, paired with a tool called edr_blind, and manually clears Windows event logs afterward to cover its tracks. StreamRat Android banking trojan spread to 570,000 users via Meta and TikTok streaming-service ads

Malwarebytes disclosed StreamRat, an Android banking trojan and infostealer distributed through Meta ads for a fake free streaming service running Jun 11-Jul 3, 2026, with the same promotional banners simultaneously pushed on TikTok; the campaign exposed an estimated 570,000 people, overwhelmingly Spanish-speaking users located in Spain. Victims received social-engineering instructions tailored to their entry point (Instagram, TikTok, Facebook, or a plain browser) that coached them past Android's unknown-sources installation warnings; once installed, StreamRat can monitor the screen, capture keystrokes, overlay fake login screens to steal credentials, and grant attackers remote device control. Malwarebytes detects the payload under three signatures but did not publish package names, APK hashes, or C2 infrastructure. Durable catch: any Android install flow that walks a user step-by-step through disabling the unknown-sources warning, tailored to the specific app/ad the victim just clicked, is StreamRat's exact delivery mechanism — the coaching itself is the tell, regardless of which streaming brand is being impersonated this month.
